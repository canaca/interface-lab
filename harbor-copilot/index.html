Concept · AI-built

Helping sales reps clean up stalled deals without losing control

The copilot proposes a change set across many deals. The rep sees every change inside the table, picks what to apply, and can undo any of it.

Cesar Navarro · cnavarro.business@gmail.com

Problem
Pipelines rot: deals go quiet, owners leave, close dates slip. Fixing it is tedious, and letting an AI edit the CRM in bulk feels risky.
User
A sales manager cleaning up the team pipeline before a forecast call.
Decisions
  1. The diff lives in the cell. Old value crossed out, new value below, with the reason. No separate review screen.
  2. Bulk by default, risky by exception. Safe changes are pre-selected. Closing a deal is never pre-selected.
  3. Conflicts are shown, not overwritten. If a teammate edited a deal after the copilot looked, that deal is held until the rep chooses.
  4. Partial failure is precise. It names the changes that failed and confirms the rest were applied.
  5. Undo at every level. Undo one change from the log, or undo the whole set.
Outcome
An AI-built concept of the full change-set flow: scan, review, bulk apply, conflict, partial failure and undo, plus empty and loading states. Not yet tested with real users or a real CRM.
Label
Concept. The company, people and deals are fictional. The interface and its state flow are real and run in the browser.
